1

Notification dot competes with primary action

The bell icon with a red dot pulls eye-weight away from the main "Upload & Extract" CTA. First-time users glance up-right before they glance down.

H1 · Visibility of system status
2

"Generate via AI" doesn't visually dominate

All three cards have equal visual weight. The primary path (AI) and the inactive path (Template, "Coming Soon") read the same size, same gradient, same iconography. User has to read every word to choose.

H6 · Recognition over recall
3

"Coming Soon" wastes prime real estate

An entire one-third of the screen is allocated to a feature that doesn't work yet. New users still need to figure out it's disabled before they move on.

H8 · Aesthetic & minimalist
4

"Pending" status is ambiguous

Files show "Pending" before any extraction has even been triggered. Users can't tell if "Pending" means "uploaded, waiting for AI" or "not yet uploaded, click Extract to start".

H1 · Visibility of system status
5

"5 of 25 files" — what's 25?

The cap appears without explanation. Why 25? File limit? Account quota? Document type cap? No tooltip, no info icon.

H10 · Help & documentation
6

No file remove / preview affordance

Once a file is in the queue, user can't preview it inline, can't remove it, can't reorder it. The X to dismiss is non-obvious or missing.

H3 · User control & freedom
Quick fix

Promote the AI path to a hero card (60% width) with a small "Other options →" link revealing Template + Manual. Mark "Coming Soon" with a dashed border, not a full card. Show file states as "Uploaded · ready", not "Pending", and put per-file X + preview affordances on hover.

1

Two parallel navigation systems again

The breadcrumb ("Eicore / Product Config / New Product / AI Extraction Preview") AND the 4-step stepper both narrate where the user is. They duplicate each other and add no information about what's next.

H4 · Consistency & standards
2

"Documents" toggle has zero affordance

A blue toggle labelled "Documents" sits next to the 89% score with no apparent function. Toggle what? Hide the left pane? Switch source view? Compare docs? Unguessable.

H10 · Help & documentation
3

Confidence chips contradict the score

The big score says "130 of 145 with high confidence". The chips below say "6 High / 0 Medium / 0 Needs Attention". 6 ≠ 130. Two different denominators, no reconciliation.

H1 · Visibility of system status
4

Note severity tints conflict

"Missing fields" tinted critical-red. "Multi-source variants" tinted amber. "Ambiguous values" also amber. But the severity scale isn't documented — is a missing field worse than an ambiguous value? User must guess.

H9 · Error recognition
5

Sections collapsed by default — no preview of risk

"8 sections, all collapsed" means user must expand each one to find out which fields are weak. No glance-level risk distribution.

H6 · Recognition over recall
6

"Expand all / Collapse all" loses scroll context

Click "Expand all", the screen jumps. User loses their place. No section-level memory of state.

H7 · Flexibility & efficiency
Quick fix

Replace the redundant stepper with a single line under the breadcrumb showing only the current + next step. Reconcile the confidence counts into one strip: "130 high · 9 medium · 6 needs attention" — same denominator throughout. Auto-expand the weakest section by default so the user lands on the most important triage point.

1

Section score appears twice

"92%" shown in the collapsed header AND again as a full progress bar in the expanded body. Three different visual encodings of the same number. Cognitive cost.

H8 · Aesthetic & minimalist
2

All three plans show 92% — looks templated

Mini, Medi, and Max all return identical 92% confidence. This is either a real signal (AI calibrated uniformly) or noise (defaulted). Without a confidence breakdown by underlying signal, it's impossible to tell.

H1 · Visibility of system status
3

No cross-plan comparison

The user's main task at this step is to verify the progression from Mini→Medi→Max makes sense. The table forces sequential reading of three paragraph descriptions. No side-by-side numeric comparison.

H6 · Recognition over recall
4

"From: BRD" pill doesn't link to source

The pill suggests provenance but offers no click-through. To verify, user has to manually scroll the left pane document. Two-step lookup for what should be a one-click jump.

missing affordance
5

Long descriptions cramped in narrow column

"Entry-level plan with sum insured of Rs.4L or Rs.5L. Floater available for Self+Spouse/LP+Children." is multiline prose inside a tabular cell. Information density mismatches the visual container.

H8 · Aesthetic & minimalist
Quick fix

Replace the row-per-plan table with three vertical comparison columns side-by-side: each column is a plan with its key numeric values (SI min/max, floater scope, key benefits) as a bullet stack. Visual diff at a glance. Make the "From: BRD" pill clickable — it scrolls the left pane and highlights the source sentence.

1

Two parallel progress models

The 7-step pipeline at the top AND the 5-stage Builder Roadmap on the left rail (not shown here but present in the live screen) both claim to track progress. They overlap and disagree about what counts as a "stage".

H4 · Consistency & standards
2

"30/30" — ambiguous denominator

Is it 30 needing attention out of 30 total flagged? Or 30 of 30 already addressed? In English it could mean either. The user pauses to interpret.

H1 · Visibility of system status
3

Product tree, copy #1 of 3

The left rail navigation IS a product tree (Plans → Mini/Medi/Max). Same structure rendered again in the middle (Plan cards) and the right (Tree tab). Three copies, one screen.

H8 · Aesthetic & minimalist
4

"0 fields need review" contradicts the banner

The Overview confidently states "0 fields need review · 0 sections flagged" in brand-green type. The yellow banner directly above says "30/30 needs attention". User can't tell which is the source of truth.

H1 · Visibility of system status
5

Plan cards show counts, not values

"Plan Limits 1 · Member 6 · Premium 3 · Coverages 37" — these are counts of items, not the values the user needs to verify. The actual data (e.g. "Sum Insured ₹4L–₹5L") is buried two clicks deep.

H6 · Recognition over recall
6

4-tab right panel fights for attention

Tree / Extr. / Iss. / Docs — four parallel surfaces. Each tab switch loses the user's place in the others.

H7 · Flexibility & efficiency
Quick fix

Collapse the 7-step pipeline into the existing left-rail roadmap. Replace the plan-card counts with extraction-health cells — one cell per field, coloured by confidence. Merge the 4-tab right panel into a single live activity feed (already validated in your variations).

1

Red boxes are signal, not action

Age · Family Construct · Pre-existing Conditions are wrapped in red boxes. But no inline action — clicking just selects, doesn't navigate to the fix flow.

H9 · Error recognition
2

"Age" — missing what, exactly?

Is the age value missing? The age range? The validation rule? No subtitle, no tooltip, no diagnostic. User must remember from somewhere else.

H9 · Error recognition
3

Three red items, all equal weight

No severity ranking among the three. Are they all blockers? All warnings? Should the user fix Age first or Family Construct first? Order matters for workflow time.

H6 · Recognition over recall
4

Deep nesting: 4 levels indent

Product → Plans → Mini → Premium Raters → Age. Each indent eats horizontal space and visually demotes the bottom item. The actual problems are the most-indented, least-visible nodes.

H8 · Aesthetic & minimalist
5

All-caps tree node labels

"PLAN LIMITS · MEMBER DETAILS · COVERAGES · PREMIUM RATERS" feels like internal database table names, not user-facing labels. Mixed case + sentence labels would scan better.

H2 · Match with real world
6

Center pane unchanged when tree expands

User expands Mini in the right tree, expecting to see Mini details in the middle. But the middle stays on Overview. No coupling between tree selection and main canvas.

H1 · Visibility of system status
Quick fix

Each red item becomes a feed entry with: subtitle ("missing value · expected age band"), severity ("Blocker"), and an inline "Fix →" link that opens the form on the right field. Couple tree selection to the centre canvas — clicking Mini in the tree should swap the middle pane to Mini details, not stay on Overview.

1

The "Post-hoc Shock"

This is the first time the user sees "2 blocking errors". These problems existed back in Screen 4 and 5 — they were buried under counts and tree nodes. By the time the user arrives here, they've already invested an hour. Critical surprise at the worst moment.

H1 · Visibility of system status
2

Blockers and warnings stacked together

The Publishing Checklist mixes two severity bands in one list. Visually they're distinguished by tint, but the list doesn't group them or sequence them. User reads top-down, no severity-first ordering.

H9 · Error recognition
3

No "Resolve" affordance on items

Each checklist row has the problem but no inline button to fix it. User has to navigate elsewhere (where?) to address each item. Cognitive cost: remembering 5 things to do.

H3 · User control & freedom
4

"Field Confidence" data is now visible too late

"Terms & conditions: 38% Poor · Grace period: Missing". This information existed back at Screen 2 (Extraction). Why does the user see it for the first time here? Because the extraction screen showed aggregate scores, not field-level.

H1 · Visibility of system status
5

Three "subsystem" cards are arbitrary

Why these three groupings (Rules / Field Confidence / Members & Raters)? Why not also "Coverages summary", "Document quality"? The categories appear here without context anywhere else in the journey.

H4 · Consistency & standards
6

"Submit for Approval" is the only forward action

Greyed out due to blockers, but with no path indicated to unblock. User has to back-navigate to find the right field, fix it, and return. No "Fix and continue" flow.

H3 · User control & freedom
Quick fix

Surface blockers earlier: the same banner that lives here ("Not ready to publish · 2 errors") should appear at the top of the Builder Workspace from the moment the user lands. Each row in the checklist is a deep-link that jumps to the offending field in edit mode. Group by severity: blockers, then warnings, then verified — with a horizontal severity bar visualising counts.

07 — Cross-cutting themes

Five problems that repeat across the journey.

Each theme below appears on 3+ screens. Fixing them addresses dozens of individual violations at once.

A

Two parallel navigation systems contradict each other

Every screen carries both a breadcrumb-style stepper AND a roadmap-style stage indicator. They duplicate, sometimes disagree, and split user attention.

Appears on: Screens 02 · 03 · 04 · 05 · 06
B

Confidence numbers never reconcile

Screen 02 says "130 of 145 high" but the chip strip says "6 High". Screen 04 says "0 fields need review" but the banner says "30/30 needs attention". Different denominators, no truth.

Appears on: Screens 02 · 03 · 04 · 06
C

The product tree is rendered 2–3× per screen

Left rail + middle plan cards + right tree tab. Same hierarchy, three encodings. None is the single source of truth.

Appears on: Screens 04 · 05
D

Errors lack actionable context

Red items (Age, Family Construct, Pre-existing) tell the user that something is wrong but never what, where, or how to fix. No inline diagnostic, no jump-to-fix, no severity ordering.

Appears on: Screens 04 · 05 · 06
E

Critical information arrives too late

"38% Poor confidence on Terms & conditions" first appears on Screen 06. "Hospitalisation sub-limits not configured" first appears on Screen 06. Both should have been flagged on Screen 02 (Extraction) — the moment AI extracted them.

Appears on: Screens 02 → 06 (the entire delay)
08 — Unified recommendations

Seven moves that compress the journey by 2×.

Each recommendation targets a recurring theme. Applied together, they take Priya from "3-hour reality" back to the "1-hour design target".

01

One progress model, not two.

Pick the Builder Roadmap (5 stages) as the canonical model. Drop the 7-step pipeline strip on the Builder screens. Drop the 4-step stepper on the Extraction screens. Every screen shows one progress indicator, in one location.

02

One unified confidence counter, same denominator throughout.

From Screen 02 onwards, every screen carries the same chip: "21 to review · 2 critical · 109 verified". Each token clickable, each linked to the underlying fields. No more "0 vs 30/30" contradictions.

Affects 02 Affects 04 Affects 06
03

Replace the three product trees with one Extraction Health Heatmap.

Centre canvas of the Builder Workspace becomes a 10×N grid of cells — one per field, colour-coded by confidence. Click a cell → jump to that field's edit form. Spot risk at a glance instead of clicking through three tree views.

Affects 04 Affects 05
04

Replace the 4-tab right panel with one Live Activity feed.

Tree / Extraction / Issues / Docs become a single scrollable list. Five event types: Critical · Warning · AI Hint · Suggestion · Verified. Filter chips at top. Each item carries its source citation and a one-click "Resolve →" action.

Affects 04 Affects 05
05

Surface blockers from the moment they're detected.

The "Not ready to publish · 2 errors" banner on Screen 06 should appear on Screen 02 (Extraction) the moment the AI flags those fields. User addresses them in flow, not at the gate. Eliminates "Post-hoc Shock".

Affects 02 → 06
06

Every error gets a "what, where, why, fix" payload.

Red items in the tree become structured: title · subtitle · severity · source citation · inline Fix button. Clicking "Fix" opens the right field in edit mode with the source passage highlighted. No more orphan red items.

Affects 04 Affects 05 Affects 06
07

Cross-plan comparison is the default, not the toggle.

Wherever the user lands on a plan-specific value (Mini OPD, Medi OPD, Max OPD), show the values for the other two plans alongside automatically. Horizontal comparison bars on one axis. Mental diffing → visual diffing.
